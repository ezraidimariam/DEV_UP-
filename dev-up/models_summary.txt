# DEV_UP Models Summary for Claude Analysis

## Core Models (8 Essential Classes)

### 1. User Model
- **Purpose**: Authentication and user management
- **Key Attributes**: id, name, email, password, role, level, points
- **Relationships**: 
  - hasMany challenges, focus_sessions, progressions, submissions, reponses
- **Roles**: admin, formateur, apprenant
- **Special Features**: Extends Laravel Authenticatable

### 2. Challenge Model  
- **Purpose**: Core learning content
- **Key Attributes**: id, categorie_id, titre, description, difficulte, valeur_points
- **Relationships**:
  - belongsTo Category
  - hasMany Questions, Submissions, UserChallenges
  - belongsToMany Users
- **Difficulty Levels**: debutant, intermediaire, avance, expert

### 3. FocusSession Model
- **Purpose**: Pomodoro-style timer functionality
- **Key Attributes**: id, user_id, focus_duration, break_duration, date_session, is_completed
- **Relationships**: belongsTo User
- **Constraints**: focus_duration (1-120min), break_duration (1-30min)

### 4. Category Model
- **Purpose**: Challenge organization
- **Key Attributes**: id, nom, description, icone, couleur, is_active, ordre
- **Relationships**: hasMany Challenges
- **Features**: Hierarchical ordering, visual customization

### 5. Question Model
- **Purpose**: Individual questions within challenges
- **Key Attributes**: id, challenge_id, enonce, type, points, ordre
- **Relationships**:
  - belongsTo Challenge
  - hasMany Reponses
- **Types**: qcm, code, texte, vrai_faux

### 6. Reponse Model
- **Purpose**: User answers to questions
- **Key Attributes**: id, question_id, user_id, contenu, est_correcte, points_obtenus
- **Relationships**: belongsTo Question, belongsTo User
- **Features**: Score calculation, time tracking

### 7. Progression Model
- **Purpose**: User progress tracking
- **Key Attributes**: id, user_id, challenge_id, niveau_actuel, points_obtenus, pourcentage_completion
- **Relationships**: belongsTo User, belongsTo Challenge
- **Status Tracking**: en_cours, termine, abandonne

### 8. Submission Model
- **Purpose**: Challenge submissions with evaluation
- **Key Attributes**: id, user_id, challenge_id, contenu, feedback, note, statut
- **Relationships**: belongsTo User, belongsTo Challenge, belongsTo evaluator (User)
- **Workflow**: en_attente → en_cours → termine/rejete

## Key Relationships Summary

```
User 1--* Challenge (creates)
User 1--* FocusSession (has)
User 1--* Progression (tracks)
User 1--* Submission (submits)
User 1--* Reponse (answers)

Challenge 1--* Question (contains)
Challenge 1--* Submission (receives)
Challenge 1--* Progression (generates)
Challenge *--1 Category (belongs_to)

Question 1--* Reponse (receives)

Submission 1--1 User (belongs_to)
Progression 1--1 User (belongs_to)
Progression 1--1 Challenge (belongs_to)
Reponse 1--1 User (belongs_to)
Reponse 1--1 Question (belongs_to)
```

## Business Logic Flow

1. **User Registration** → User created with role
2. **Challenge Creation** → Formateur creates Challenge in Category
3. **Question Setup** → Challenge contains multiple Questions
4. **User Engagement** → User starts Challenge → Progression created
5. **Learning Process** → User answers Questions → Reponses created
6. **Submission** → User submits work → Submission created
7. **Evaluation** → Formateur evaluates → Feedback added
8. **Progress Update** → Progression updated with points/completion
9. **Focus Sessions** → User tracks study time → FocusSession records

## Data Integrity Constraints

- **Foreign Keys**: All relationships properly constrained
- **Check Constraints**: Points >= 0, Levels 1-10, Duration limits
- **Unique Constraints**: User emails, User-Challenge combinations
- **Enum Constraints**: Roles, difficulties, statuses limited to predefined values

## Performance Considerations

- **Indexes**: All foreign keys and frequently queried fields indexed
- **Soft Deletes**: Not implemented (hard deletes for simplicity)
- **Timestamps**: All tables include created_at/updated_at
- **Cascading**: Proper CASCADE/SET NULL for data integrity
